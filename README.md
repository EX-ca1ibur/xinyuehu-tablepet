# 心月狐桌宠 · 显示当前模型与花费

《鸣潮》心月狐的 Windows 桌宠，实时显示 **DSH 当前使用的模型** 和 **花了多少钱**。

> 📦 **本仓库只含代码，不含任何图片素材**（`assets/`、`docs/` 已排除）。
> 角色图集请自行安装：`npx petdex install hsin-moon-fox`
> 图集缺失时程序会**弹出提示框**说明原因并退出，不再抛 traceback 崩溃。

角色素材用的是网上现成的同人桌宠图集（见下方"素材来源"），不是手绘近似图。

```
┌───────────────────────────┐
│ ● 心月狐  推理 max   ¥1.87 │   ← 用量浮窗
│ deepseek-v4-flash         │

│ 余额 ¥55.84               │
└─────────────▽─────────────┘
        （心月狐精灵）
```

## 一、快速开始

双击 `start-pet.cmd` 即可（无控制台窗口）。

命令行等价写法：

```powershell
& "$env:DSH_HOME\dsh-runtimes\dsh-primary-runtime\dependencies\python\pythonw.exe" `
  "src\run_pet.py"
```

可选参数：`--size 200`（精灵尺寸）、`--no-hud`（先不显示浮窗）、`--demo`（用演示数据截图）。

## 二、交互

| 操作 | 效果 |
|---|---|
| 左键拖动 | 移动桌宠；松手时靠近底部会吸附任务栏 |
| 单击 | 摸摸头（挥手动画） |
| 双击 | 跳一个 |
| 右击 | 菜单：跳一个 / 显示用量浮窗 / 总在最前 / 贴底吸附 / 大小 / 立即刷新 / 打开发用量账本 / 退出 |
| Esc | 退出（焦点在窗口上时） |

模型开始花钱时（今日花费增加），她会自动做一段"工作中"的跑步动画。

同一时间只运行一只：用 `~/.dsh/xinyuehu-pet.lock` 里的 PID 判活，重复启动会直接提示退出。

**注意**：装了自启之后，只要看门狗还活着，右击「退出」只关掉当前这只，几秒后会被重新拉起。想彻底关掉，先运行 `uninstall-autostart.cmd`（它会先停看门狗、再停桌宠）。

## 三、打开 DSH 就自动启动桌宠（默认已装）

`install-autostart.cmd` 已经装好了。机制是一个**轻量看门狗**（`run_pet_watchdog.py`），每 2 秒检查一次：

| 状态 | 看门狗的动作 |
|---|---|
| DSH 在跑、桌宠不在（首次或崩了） | 拉起桌宠（桌宠自带 PID 锁，手动开的那只会被"认领"，不会开出第二只） |
| DSH 在跑、桌宠也在 | 什么都不做 |
| DSH 已退出 | 停掉桌宠，然后等 DSH 回来 |

所以无论你用开始菜单、桌面快捷方式还是别的方式打开 DSH，桌宠都会跟着出现；DSH 一关，桌宠也一起收尾，不留后台常驻进程。

- **自启项**：`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\xinyuehu-pet.vbs`
  （安装时会把项目绝对路径写进这个 vbs——它放在启动文件夹里，无法用自身位置找到项目）
- **日志**：`~/.dsh/xinyuehu-pet-watchdog.log`（超过 256KB 自动截断，只留最近 400 行）
- **卸载**：`uninstall-autostart.cmd`（删自启项并停掉看门狗与桌宠）
- **只停不卸**：`stop-pet.ps1`——它会先停看门狗再停桌宠，顺序不能反，否则看门狗会立刻把桌宠拉回来
- **重装**：再跑一次 `install-autostart.cmd`
- **只手动开、不要自启**：先卸载，然后双击 `start-pet.cmd`

看门狗只用 `tasklist` + `ctypes` 判活，不轮询 PowerShell——那样每 2 秒起一个进程太慢，而且中文进程名会在按 UTF-8 解码时直接抛异常。

### 素材丢失了怎么办（已真实发生过一次）

真实图集在 `~/.codex/pets/hsin-moon-fox/spritesheet.webp`。它**曾经消失过**（目录里只剩 `pet.json`），当时程序静默回落到手绘替代立绘，看起来就像"宠物变了"。现在有三重防护：

1. **一键恢复**：`python tools/restore_pet_art.py`——临时下载 petdex CLI 重新拉取素材，不污染项目目录
2. **浮窗明确告警**：素材缺失时卡片顶部出现红条「桌宠素材缺失 · 正使用替代立绘」，不再默默画错角色
3. **看门狗巡检**：每 60 秒检查素材，丢失或恢复都写进 `~/.dsh/xinyuehu-pet-watchdog.log`；素材恢复后自动重启桌宠改用真图

也可以手动把 `spritesheet.webp` 放回该目录，然后重启桌宠。

### 自启的两个坑（都已修）

- **`%DSH_HOME%` 在全新登录环境里是未定义的**。启动器原先用它拼 Python 路径，失败后回落到裸 `python.exe`，结果用了系统里另一个 Python（本机是微软商店版）——那个解释器没有 Pillow/numpy，于是每次启动都失败、看门狗无限重启。现在安装时把**绝对路径直接写进 vbs**，找不到就报错退出，不再静默回落。
- **看门狗单例存在竞态**：两个实例同时启动会双双认为自己该运行，于是出现两只宠物和重启风暴。现在用 OS 文件锁（`msvcrt.locking`），原子且进程退出即释放。

## 四、数据从哪来（实时，且可核对）

**主数据源是会话日志**，不是账本。原因见下面「为什么不用账本」。

会话日志：`~/.dsh/sessions/<工作目录>/<会话>/session.v4.jsonl.zstd`

| 显示项 | 来源 |
|---|---|
| 当前模型 / 推理等级 | 会话日志里的 `request/context` 与 `request/header`；**会话中途换模型也会跟着变**（按声明顺序逐段归属每次调用） |
| 今日 / 累计 / 本会话花费 | 逐条 `assistant/message` 的真实 token 用量，按**每次调用自己那一刻的时段**计价后求和 |
| 上下文 | 最近一次调用实际发送的提示词 token（`输入+缓存读+缓存写`）÷ 上下文窗口；窗口值取自会话日志（本机 1,000,000） |
| 余额 | `~/.dsh/dsh-usage/provider-snapshots.json` 的 `balance`（唯一只能由 DSH 刷新的项） |
| 状态圆点 | 绿=会话日志在 2 分钟内有写入，黄=较久，红=读不到 |

### 计价公式（与 DSH 自带价目表一致）

单位：CNY / 百万 token；峰时=北京时间工作日 09:00–12:00 与 14:00–18:00，其余时段半价。

| 模型 | 缓存命中 | 未命中输入 | 输出 |
|---|---|---|---|
| `deepseek-flash` | 0.02 / 0.04 | 1.0 / 2.0 | 4.0 / 8.0 |
| `deepseek-v4-pro` | 0.15 / 0.30 | 4.5 / 9.0 | 13.5 / 27.0 |

```
花费 = (缓存读×缓存价 + (输入+缓存写)×未命中价 + 输出×输出价) / 1e6
```

**这个公式是核对过的**：拿账本里已有的记录反算，非峰谷时段一条不差（`0.109514`、`0.335889`、`0.085470` 全部精确复现）；唯一对不上的那条是跨了峰谷的记录，差值正好是一半——说明它是逐次调用按当时时段计价的，本程序用的就是同一套。

### 为什么不用账本（原来的问题）

原先读 `~/.dsh/dsh-usage/usage-ledger.json`，但在这台机器上：它的 mtime 可能比最后一次活动**旧一整天**，而且里面只记了**单个会话**的量。结果是"今日 ¥0.00 / 累计 ¥0.74"这种冻结数字，一整天不动——这就是"用量不对、也不实时"的原因。

会话日志则每个 step 都在追加，所以数字会随对话推进。

程序**只读**这些文件，不写、不改任何 DSH 数据。

## 六、桌面透明是怎么做到的

tkinter 的 `-transparentcolor` 只能做**二值**透明（一个像素要么画要么不画），做不了半透明光晕。所以：

- 主体、边框、文字全部输出为**不透明**像素，边缘保留抗锯齿 → 轮廓干净；
- 低透明度的"半死"像素在烘焙阶段按**合成后有效可见度**（alpha × 与色键的对比度）决定保留或删除，避免抖动成脏点；
- 进程必须在创建窗口前设置 **per-monitor DPI 感知**，否则 Tk 报逻辑尺寸、坐标按物理尺寸解释，桌宠会被放到屏幕外（这个坑已修）。

本程序与 DSH 内置宠物共用同一份图集，二选一即可：

1. 打开 设置 → 宠物，选择 **心月狐**（若列表里还没有，重启 `dsh web` 后出现，注册表在启动时构建一次）；

3. 本程序的优势就是那份用量浮窗，两者可以同时开。
